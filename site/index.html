업로드한 문서의 변환과 분석

사용자가 올린 PDF를 검색과 답변에 활용할 수 있도록 내용을 추출·복원하고, 여러 문서를 처리하는 대기 시간을 줄이는 작업입니다.

  • PDF → Markdown 변환 문제: 오픈소스 변환에서 표·수식이 손상됐고, 전체 AI 변환에도 오류와 호출 부담이 남음. 해결: PDF 변환 오픈소스를 비교해 AnyDoc 채택. 깨진 본문만 AI로 복원. 표·수식은 별도 처리하고 그림은 원본 보존. 성과: PDF 30쪽의 내부 평가 통과율 45.17% → 89.89%.
  • 문서의 Wiki 생성 병렬화 문제: 앞선 문서의 외부 AI 응답을 기다리는 동안 뒤의 문서 처리가 지연. 해결: Worker 수와 내부 동시 요청 수를 각각 변경하며 비교. 메모리 증가를 고려해 Worker 최대 4개를 채택하고, 오히려 느려진 추가 동시 요청, GPU 병렬화는 제외. 성과: 문서 4개 분석 시간 282.11초 → 73.89초(약 74% 감소)

RAG 과정의 검색 정확도 개선

사용자 질문과 관련된 내용을 저장된 문서에서 찾아 AI 답변의 근거로 제공하는 기능입니다. 필요한 근거를 빠뜨리지 않고, 답할 자료가 없는 질문은 구분하도록 개선했습니다.

  • 답변 근거 선택 개선 문제: 기존 검색이 필요한 근거를 놓치고, 답이 없는 질문에도 근거를 반환. 해결: 라우팅에서 효과를 본 선택형 판단 모델 Jev를 RAG에 적용. 전체 근거 실험 후 동일 후보·반환량으로 비교 조건을 맞추고, 후보 300개·최대 4병렬로 조정. 성과: 논문 9편의 평가에서 답이 있는 80문항의 근거 충족률 66.25% → 91.25%. 답 없는 20문항의 잘못된 근거 반환 20 → 0건. Jev 최적화 전후 시간 중앙값 9.090초 → 2.251초.

AI Agent와 Skill

사용자가 말로 요청한 문서 편집과 폴더 정리를 AI가 수행하는 기능입니다. 또한, 변경 내용을 사용자가 승인한 뒤 반영하도록 하고, 반복 작업을 지침으로 저장해 재사용할 수 있게 만들었습니다.

  • 사용자 정의 작업 지침(Skill) 문제: 사용자마다 다른 반복 작업을 개발자가 모두 기능으로 추가하기 어려움. 해결: 자연어 지침의 작성·검토·게시 기능과 권한·승인 우회 검사를 구현. 실제 문서 변경은 미리보기를 확인한 뒤 별도로 승인하도록 설계. 성과: 게시한 Skill을 Agent에서 사용가능하도록 구현. 문서 6개 검증에서 승인 전 변경 없이, 승인 후 폴더 3개 생성과 문서 이동 확인.
  • 문서 편집 품질 개선 문제: 생성한 편집 초안이 사용자의 편집 의도를 충족하지 못하는 사례 발생. 해결: 편집 목적 전달과 재시도 입력을 개선하고, 의미 평가 후 최대 1회 재작성 적용. 성과: 동일 초안 114개의 내부 평가 통과 94 → 104건.

서비스별 책임과 통신 구조 설계

AI 기능을 포함한 서비스의 책임과 데이터 소유권, 서비스 간 통신 방식을 정하는 작업입니다. 초기 설계를 제안하고 팀원·멘토와 함께 최종 구조를 완성했습니다.

  • MSA 초기 설계 제안 후 팀원·멘토와 데이터 소유권, 서비스 경계, 통신 방식을 논의해 최종 구조 공동 설계.

데이터 정제 파이프라인 구축

약 4만 4천 건의 의약품 원문을 사용자가 이해하기 쉬운 표현으로 바꾸는 작업입니다. 반복되는 설명은 한 번만 변환하고 각 약품에 연결해 비용을 줄였습니다.

  • 문제: 약 4만 4천 건의 약품 원문을 모두 쉬운 설명으로 변환하면 API 비용 약 $200 예상. 해결: 완전 일치 문장 → 의미가 같은 문장 순으로 중복 제거. 누락된 5%는 성분별 주의사항으로 보완하고, GPT Batch API로 변환한 뒤 약품별로 재연결.

    성과: 변환 대상 1GB → 326MB. 전체 원문 변환 예상 비용 약 $200 대비 실제 API 지출 $11.18.

    비용은 예상치와 실지출의 비교이며 전처리 인건비는 제외했습니다.

개인 건강 정보를 기반으로 답변하는 AI 복약 챗봇

사용자가 증상을 자연어로 물으면 관련 약품과 복약 정보를 찾는 기능입니다. 건강 프로필은 내부에서 판단해 개인화에 활용하고, 외부 AI에 보내는 정보와 분리했습니다.

  • 문제: 일상적인 증상 표현과 약품 효능의 용어가 다르고, 개인화에 필요한 건강 정보는 외부 AI에 전달하기 어려움. 해결: Weaviate 의미 검색과 AI 오케스트레이션으로 약품 탐색·복약 위험·섭취량별 처리 경로 구성. 임신 여부·복용약·기저질환은 내부 코드로 판단. 성과: 자연어 증상으로 약품 정보를 탐색하고, 해당 건강 프로필을 외부 LLM 입력에서 제외한 개인화 흐름 구현.
