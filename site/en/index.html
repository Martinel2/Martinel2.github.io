Document conversion pipeline and faster Wiki generation

Converted uploaded PDFs for retrieval and grounded answers, and reduced Wiki generation time. Internal pass rate on 30 pages improved from 45.17% to 89.89%; analysis of 4 documents fell from 282.11s to 73.89s.

  • PDF → Markdown conversion Problem: Open-source conversion damaged tables and equations; full AI conversion still had errors and high API usage. Solution: Compared PDF tools and adopted AnyDoc. Repaired damaged text with AI, processed tables and equations separately, and preserved original figures. Result: Internal pass rate on 30 PDF pages improved from 45.17% to 89.89%.
  • Parallel Wiki generation Problem: Later documents waited for earlier external AI responses. Solution: Compared worker counts and requests per worker. Capped workers at 4 to manage memory; rejected extra concurrency and GPU parallelism that slowed processing. Result: Analysis of 4 documents fell from 282.11s to 73.89s (about 74% less).

Improving retrieval for grounded AI answers

Retrieved document evidence for AI answers. Coverage on 80 answerable questions rose from 66.25% to 91.25%, while false evidence returns on 20 unanswerable questions fell from 20 to 0.

  • Evidence selection for RAG Problem: Retrieval missed required facts and returned evidence for unanswerable questions. Solution: Applied Jev after routing tests, then controlled candidates and return limits after a full-corpus trial. Tuned to 300 candidates and up to 4 parallel batches. Result: Across 9 papers, coverage on 80 answerable questions rose from 66.25% to 91.25%. False evidence returns on 20 unanswerable questions fell from 20 to 0. Median time before/after Jev tuning: 9.090s → 2.251s.

Reusable Skills and improved AI Agent routing

Built reusable Skills with user approval before changes. Applied Jev to route requests to questions, edits and other tasks: correct decisions rose from 77/98 to 81/98, and median decision time fell from 8.967s to 0.658s.

  • User-defined task instructions (Skills) Problem: Developers cannot build every recurring workflow users need. Solution: Built drafting, review and publishing of natural-language instructions, with checks against bypassing permissions or approval. Document changes require separate preview and approval. Result: Published Skills became available to the Agent. In a 6-document check, no changes occurred before approval; 3 folders were created and documents moved afterward.
  • Jev-based request routing Problem: Misclassifying questions as edits led to the wrong action. Solution: Applied Jev to select task types and additional conditions for questions, edits, document creation and folder organization. Result: Fully correct decisions on the same 98 requests rose from 77 to 81. Median decision time fell from 8.967s to 0.658s.

Drug data preparation pipeline

Rewrote about 44,000 drug records in plain language. Deduplication reduced input from 1GB to 326MB; after filling missing information, conversion cost $11.18 in actual API spending versus about $200 estimated for the original text.

  • Problem: Converting all 44,000 drug records was estimated to cost about $200 in API calls. Solution: Removed exact duplicates, then semantically equivalent sentences. Filled the missing 5% with ingredient-specific precautions, converted via GPT Batch API and mapped results back to each drug.

    Result: Conversion input shrank from 1GB to 326MB. Actual API spending was $11.18 versus about $200 estimated for all original text.

    Estimated cost versus actual spending; preprocessing labor is excluded.

AI medication chatbot using health profiles

Found drug and medication information from natural-language symptoms. Evaluated health profiles internally, separately from information sent to external AI.

  • Problem: Everyday symptom language differed from drug indications, while sensitive health data needed to stay out of external AI inputs. Solution: Used Weaviate semantic search and AI orchestration for drug discovery, medication risks and dosage. Evaluated pregnancy, current medications and underlying conditions in internal code. Result: Implemented personalized symptom-based search while excluding those profile fields from external LLM inputs.
